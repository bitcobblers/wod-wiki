Architecture & Quality Engineering Review

Wod.Wiki Dogfood Report: Comprehensive Technical Review & Remediation Plan

Target: https://wod.wiki (Release v0.35.2124) · Test Date: 2026-10-13 · Author: Senior Engineering Lead · Scope: 11 Findings (1 High, 4 Medium, 6 Low) across Navigation, Seed Engine, Storage, and UI Surfaces

1. Executive Summary & Engineering Assessment

The exploratory dogfood assessment of Wod.Wiki v0.35.2124 confirms that the application's core foundational engines are robust. Critical workflows—including local-first SQLite/IndexedDB storage synchronization (684 community library records imported smoothly), the time-stepped workout clock with audio/segment transitions, WQL (Whiteboard Query Language) condition compilation, and cross-screen journal persistence—operate without system crashes or data corruption.

However, the assessment identified 11 concrete quality and UX defects that erode user trust. None are architectural dead-ends. Rather, they represent classic "edge-case friction": fallback sentinels falling through unexpected branches (e.g. Date(0) Unix epoch groupings), unstyled wrapper boundaries around editor components, non-reactive one-time cache probes, and default date-windowing presets that mask newly imported data.

Following our engineering principles (Stdlib/native first, minimum diff, deletion over addition, explicit ponytail upgrade ceilings), this review details the root cause for each finding down to the exact file and line number, followed by a surgical remediation specification.

3. Deep Technical Review & Surgical Remediation Specifications

Issue 1: "Download Markdown" on Catalog Pages Exports Unrelated Welcome Notebook

High Functional
URL: https://wod.wiki/efforts (and /catalogs) · Components: apps/playground/app/lib/routeView.ts:234-263, apps/playground/app/AppContent.tsx:396, apps/playground/app/pages/shared/PageToolbar.tsx:89-127

Root Cause: In routeView.ts, deriveWorkout(route) acts as the fallback resolver for the active workout model displayed and manipulated across the application. When evaluating stream/catalog routes (like /efforts or /catalogs), namedMatch matches, and the resolver returns:

// apps/playground/app/lib/routeView.ts:258-262
return {
  name: namedMatch,
  content: PLAYGROUND_CONTENT, // "# My Workout Notebook..." welcome text
  category: 'General',
};

Simultaneously, AppContent.tsx:396 renders the <PageDownloadAction> button whenever currentWorkout.content !== ''. Because catalog views are populated with PLAYGROUND_CONTENT instead of an empty string, the toolbar surfaces the download action, which unconditionally blobs and saves currentWorkout.content.

Remediation: Set content: '' for named stream routes in deriveWorkout. Stream routes are search/facet views, not authored notebook documents; they should not expose an arbitrary notebook export unless an explicit catalog-serialization exporter is wired.

// apps/playground/app/lib/routeView.ts:258-262
-  content: PLAYGROUND_CONTENT,
+  content: '',
ponytail: Suppresses download action on stream catalogue pages. If athletes request exporting full catalog definitions (e.g. all 5 effort specs or full crosswalk lists to markdown), wire a dedicated catalogToMarkdown(catalogId) serializer to PageDownloadAction instead of the generic workout blob.

Issue 2: "Scheduled" Toast "Open" Navigates to Home Instead of Scheduled Day

Medium Functional
URL: https://wod.wiki/playground/:slug · Components: apps/playground/app/pages/PlaygroundNotePage.tsx:206-235, apps/playground/app/lib/noteIdentity.ts:20-29, apps/playground/app/lib/routes.ts:105-107

Root Cause: Two compounding bugs cause this redirection failure:

  1. In PlaygroundNotePage.tsx:231 (as well as EffortDetailPage.tsx:258, FeedItemPage.tsx:155, and FeedDetailPage.tsx:117), the toast confirmation action is coded as: 
    action: {
  label: 'Open',
  onClick: () => navigate(noteByIdPath(journalNote.id)), // navigates to /notes/<uuid>
}
    When an athlete schedules a workout for a date (e.g., 2026-10-14), their mental model is to view that day's itinerary in the journal, not the raw isolated note UUID.
  2. Worse, in apps/playground/app/lib/noteIdentity.ts:25-28, noteRefToPath(parseNoteId(id)) provides a fallback rule: if an ID lacks a recognised family prefix (journal:, playground:, etc.), it defaults to '/' (home). This fallback is pinned in noteIdentity.test.ts:25-27, which silently redirects raw UUID navigation calls to the homepage.

Remediation:

  1. Update handleScheduleBlock across all 4 scheduling pages to navigate directly to the scheduled day route: 
    // Use journalEntryPath(targetDateKey) which routes to /journal/YYYY-MM-DD
action: {
  label: 'Open',
  onClick: () => navigate(journalEntryPath(targetDateKey)),
}
  2. Fix noteRefToPath in apps/playground/app/lib/noteIdentity.ts so that any bare un-prefixed ID falls back to noteByIdPath(ref.raw) (i.e. /notes/${ref.raw}) instead of dropping the user on the landing page '/'.

Issue 3: "Only the core seed is imported" Notice Persists After Community Sync

Medium UX
URL: https://wod.wiki/feeds, https://wod.wiki/catalogs · Components: apps/playground/app/views/stream/QueriableStreamView.tsx:210-213, 422-449, 788, apps/playground/src/services/seed/seedReadiness.ts:187-197

Root Cause: The banner dismissal logic suffers from a dual lack of reactivity:

  • QueriableStreamView.tsx:788 gates the banner on profile.seedNotice && libraryMissing && !librarySynced.
  • libraryMissing is computed via useSeedLibraryMissing(), which calls readSeedCoverage() only once on component mount inside a non-reactive useEffect. When sync runs in the background or finishes from Settings, QueriableStreamView never re-probes coverage.
  • librarySynced is a local boolean state that is only set to true if the user triggered sync directly from the button inside that specific banner instance. If synced elsewhere, librarySynced remains false and libraryMissing remains true until a hard refresh.
  • Furthermore, in seedSync.ts:466-481, readSeedCoverage() checks meta.seedVersion > 0 for non-autoImport sources. The local checkpoint version was not updated upon successful ingestion, leaving the database state perpetually reporting "Update available".

Remediation: Subscribe useSeedLibraryMissing to sync activity events (via syncActivity.ts or the onSyncComplete callback). When any sync cycle completes, re-evaluate readSeedCoverage() and update state reactively.

Issue 4: Seeded "New Playground" Template Leaks Literal $CURSOR Placeholder

Medium Content
URL: https://wod.wiki/playground/2ce89ecd-c4df-5c3a-aa6f-b334a49858a9 · Components: scripts/sync-seed.ts:49-51, 79, apps/playground/app/templates/new-playground.md:4

Root Cause: apps/playground/app/templates/new-playground.md contains the template token $CURSOR on line 4 inside its ```time fence. When creating a playground dynamically via the in-app "New Playground" button, applyTemplate() in pageUtils.ts:22-30 strips $CURSOR and positions the editor caret.

However, the build script scripts/sync-seed.ts imports new-playground.md directly as a raw database seed row. Because it bypassed applyTemplate(), the literal text $CURSOR was written directly into the seeded database. When the runtime grammar classifies this block, Lezer parses $CURSOR as an exercise token, generating a bogus metric chip: 🏋 Exercise $CURSOR.

Remediation: In scripts/sync-seed.ts, sanitize template markdown files prior to packaging into the seed database:

// scripts/sync-seed.ts:79
- const templateContent = fs.readFileSync(templateRowPath, 'utf8');
+ const rawContent = fs.readFileSync(templateRowPath, 'utf8');
+ const templateContent = rawContent.replace(/\$CURSOR/g, '');

Issue 5: Journal Note Editor Visually Almost Invisible

Medium Visual
URL: https://wod.wiki/notes/<uuid>?edit=1 · Components: apps/playground/app/pages/NoteByIdPage.tsx:244-307, apps/playground/src/components/organisms/editor/NoteEditor.tsx:941

Root Cause: NoteEditor is designed as an un-bordered, headless CodeMirror component (cm-note-editor relative w-full min-w-0). Surfaces like JournalDatePage.tsx:296-299 wrap it inside a structured card container with explicit borders, headers, and backgrounds.

In contrast, NoteByIdPage.tsx:249 renders <NoteEditor> inside an unstyled flex wrapper: <div class="flex flex-col gap-4 px-4 py-6">. Without host container styling, borders, or an empty-state placeholder, the editor area appears as an ambiguous, blank gap. Additionally, the ?edit=1 search param is not hooked into any autofocus or visual editing mode trigger.

Remediation: Wrap <NoteEditor> in NoteByIdPage.tsx in standard card styling (matching EditorWindow) and provide an empty placeholder text ("Type workout markdown here...") when the note body is empty.

// apps/playground/app/pages/NoteByIdPage.tsx:287
<div className="rounded-xl border border-border bg-card/60 p-4 shadow-sm focus-within:border-accent transition-colors">
  <NoteEditor
    initialContent={note.content}
    placeholder="Write your workout or notes..."
    onChange={handleContentChange}
  />
</div>

Issue 6: Default Date Window Makes Feeds Look Empty with Misleading Message

Low UX
URL: https://wod.wiki/feeds · Components: apps/playground/app/views/stream/streamProfile.ts:127, apps/playground/app/views/stream/QueriableStreamView.tsx:660-667

Root Cause: FEEDS_STREAM_PROFILE.defaultWql is configured as ':feed{} last 2w'. Historical feed archives (such as CrossFit Games 2026 or older community posts) predate the past two weeks. When a user syncs for the first time, 684 records are imported, but the default query filters every single one out.

The empty state then renders a generic fallback: "No entries match your search." which misleads the user into thinking sync failed or the catalog is empty.

Remediation:

  1. Change FEEDS_STREAM_PROFILE.defaultWql to ':feed{}' (All time, mirroring EFFORTS_STREAM_PROFILE).
  2. In QueriableStreamView.tsx, when a date clause is present and returns 0 items while unfiltered items exist, render an informative empty state: "No feed entries found in the last 2 weeks. [Show all-time entries]".

Issue 7: Facet Panels List Hundreds of Zero-Count Values

Low UX
URL: https://wod.wiki/journal, /feeds, /playgrounds · Components: apps/playground/app/nav/panels/conditionsFacets.ts:412-417, apps/playground/app/nav/panels/FacetProperties.tsx:109-227

Root Cause: conditionsFacets.ts incorporates a helper called seedZero. For membership-backed facets (tags, effort movements), it deliberately seeds the entire corpus vocabulary with count 0 so that criteria remain selectable even before any matches exist. For the Effort facet, this injects ~570 vocabulary items into the left-rail facet accordion, 565 of which display 0 matches.

Remediation: In FacetProperties.tsx, filter out zero-count items by default unless the item is currently selected by the user:

// apps/playground/app/nav/panels/FacetProperties.tsx:120
const visibleOptions = options.filter(
  (option) => option.count > 0 || selectedValues.has(option.value)
);
ponytail: Filters out zero-count facet options in the render layer. If athletes want to discover unattempted movements to build new search criteria, add an expandable "Show unlisted movements (565)" disclosure beneath the facet list.

Issue 8: Dateless Playground Grouped Under "Jan 1, 1970"

Low Visual
URL: https://wod.wiki/playgrounds · Components: apps/playground/app/lib/entryMapper.ts:355-381

Root Cause: In entryMapper.ts:360-366, the date-resolution chain for playground entries evaluates:

// apps/playground/app/lib/entryMapper.ts:361
typeof note.targetDate === 'number'

Dateless playground notes (and canvas snapshot templates) store targetDate: 0 as a numeric sentinel representing "no assigned date". Because typeof 0 === 'number' evaluates to true, the mapper passes 0 to new Date(0), resulting in 1970-01-01 (Unix epoch). The browse view groups these notes under the header "Jan 1, 1970" instead of "Undated".

Remediation: Guard against the zero sentinel:

// apps/playground/app/lib/entryMapper.ts:361
- typeof note.targetDate === 'number'
+ typeof note.targetDate === 'number' && note.targetDate > 0

When targetDate <= 0, the fallback falls through to note.createdAt or undefined, properly grouping dateless entries under the existing "Undated" section.

Issue 9: Note Effort Chips Link to "Not Found" Effort Pages

Low UX
URL: https://wod.wiki/e/:slug · Components: apps/playground/app/pages/shared/noteContextLinks.tsx:158-174, apps/playground/app/pages/EffortDetailPage.tsx:362-398

Root Cause: In noteContextLinks.tsx, effortLinks maps every row in block_efforts directly to { to: effortPath(row.effortSlug) } without checking whether the movement exists in the Effort catalog. When an athlete clicks on an effort slug (such as bar-muscle-ups or triple-unders), EffortDetailPage queries the effort registry, finds no definition, and renders the "Effort not found" view.

Remediation: Cross-check effort slugs against the loaded effort catalog. If an effort is not in the catalog, render it as an unlinked badge or link to an Effort Search query (/efforts?q=...) rather than a direct entity detail route.

Issue 10: Browser-Locale Date Formatting Leaks into English UI

Low Visual
URL: Saved Block History, Catalog Feed Headers, Rows Table · Components: apps/playground/src/components/organisms/editor/BlockHistory.tsx:84, apps/playground/app/views/stream/ReadmeQueryBlock.tsx:29, packages/ui/src/widgets/RowsTable.tsx:25

Root Cause: While the application specifies English date conventions via src/lib/dateFormat.ts, several downstream components bypass this helper by calling raw platform formatting functions without passing a locale parameter:

  • BlockHistory.tsx:84: new Intl.DateTimeFormat(undefined, { ... })
  • ReadmeQueryBlock.tsx:29: date.toLocaleDateString(undefined, { ... })
  • RowsTable.tsx:25: date.toLocaleDateString(undefined, { ... })

In non-English environments (such as a Japanese browser locale ja-JP), these render formatted dates like 2026年10月13日 21:25:21 or 2026年7月22日周三 while the surrounding interface remains entirely in English.

Remediation: Replace un-localized formatting calls with centralized helpers in src/lib/dateFormat.ts (such as formatDateTimeMediumShort(date) and formatDateMedium(date)), or explicitly pass 'en-US' to all Intl formatters.

Issue 11: "Landing link" Sidebar Item on Catalogs Has No Visible Effect

Low Functional
URL: https://wod.wiki/catalogs · Components: apps/playground/app/lib/routeWqlShortcuts.ts:88-112, apps/playground/app/nav/panels/ConditionsNavPanel.tsx:170-186

Root Cause: In routeWqlShortcuts.ts, LANDING_LABELS and LANDING_ICONS map routes to their human-friendly display label and icon in the left-hand navigation. Neither dictionary contains an entry for '/catalogs'. As a result, the navigation code falls back to the literal string 'Landing link' with a generic bookmark icon.

When clicked, ConditionsNavPanel.tsx executes navigate('/catalogs'). Because the user is already on /catalogs and no query parameters are changed, the action produces no state transition, URL change, toast, or visible feedback.

Remediation:

  1. Add entries for '/catalogs' in routeWqlShortcuts.ts: 
    LANDING_LABELS['/catalogs'] = 'All catalogs';
LANDING_ICONS['/catalogs'] = 'library';
  2. In ConditionsNavPanel.tsx, if a user clicks the landing link while already on that route without an active query, provide an active feedback indicator (such as scrolling to top or a subtle toast confirmation).

4. Implementation Sequencing & Verification Plan

In accordance with our "Ladder of Code" philosophy, remediation should proceed in three distinct tranches, minimizing churn and maximizing immediate user impact:

Tranche 1: Zero-Risk One-Liners (Immediate Ship)

  • Issue 1: apps/playground/app/lib/routeView.ts (set content: '' for namedMatch). Eliminates bogus welcome notebook download on catalogs.
  • Issue 4: scripts/sync-seed.ts (strip $CURSOR during template row import). Eliminates phantom 🏋 Exercise $CURSOR metric chip.
  • Issue 8: apps/playground/app/lib/entryMapper.ts (guard targetDate > 0). Eliminates "Jan 1, 1970" group in playground browse view.
  • Issue 10: BlockHistory.tsx, ReadmeQueryBlock.tsx, RowsTable.tsx (replace undefined locale with src/lib/dateFormat.ts helpers). Eliminates mixed-locale date displays.
  • Issue 11: routeWqlShortcuts.ts (register '/catalogs' label and icon). Eliminates "Landing link" mystery sidebar item.

Tranche 2: Component UI & Navigation Refinements

  • Issue 2: PlaygroundNotePage.tsx and noteIdentity.ts (navigate to journalEntryPath on schedule confirmation; fix UUID fallback).
  • Issue 5: NoteByIdPage.tsx (wrap NoteEditor in card container with border and background styling).
  • Issue 6: streamProfile.ts (change default feed window to all-time; add informative empty-state message).
  • Issue 7: FacetProperties.tsx (filter out zero-count facet options unless active).

Tranche 3: Storage Reactivity & Catalog Linking

  • Issue 3: QueriableStreamView.tsx & seedReadiness.ts (reactively update seed coverage state on sync completion).
  • Issue 9: noteContextLinks.tsx (validate effort slug existence against catalog before rendering detail links).

Verification & Test Suite Coverage
