Editor systems / audit

CodeMirror typeahead has strong islands and no shared completion model.

WQL and frontmatter work well in their own editors. Note fences stop at the opening backticks. The dropdown also has three visual treatments: a custom WQL menu, CodeMirror defaults, and a separate HTML suggestion panel.

Scope and reading of "inline"

This audit covers CodeMirror editors, fenced-section dispatch, completion sources, accept behavior, tests, and menu styling. It also notes the separate frontmatter-preview combobox where it affects the design.

Recommendation: keep CodeMirror's cursor-anchored popup and make it look like the site's inline menus. Do not put the completion list into document flow. That would move text while the user types and would replace CodeMirror's positioning, keyboard handling, filtering, and accessibility work without gaining anything.

What Whiteboard Script typeahead should offer

time and log share the same grammar and dialect stack. One provider can serve both. Their runtime actions differ, not their statement syntax. Sport suffixes such as log:climbing should narrow the vocabulary.

Implementation shape

Extract one autocomplete tooltip extension

Move the WQL tooltip rules into a shared extension under packages/ui/src/extensions/. Replace hardcoded radii and shadow with tokens. Include it in the shared editor preset, WqlTextEditor, and CalcLineEditor. Keep WQL's icon renderer separate.

Unify fence resolution and dispatch by cursor section

Use one resolver for time, log, query, and wql. Route a note's query body to the existing WQL source with the same catalog inputs as standalone WQL. Preserve opening-fence and frontmatter sources outside code bodies.

Replace the global source registry with per-editor configuration

A CodeMirror facet or compartment keeps NoteEditor's captured services inside its own state. This also makes provider order explicit instead of dependent on registration order.

Add the Whiteboard Script provider

Build syntax-node-aware slots, then attach the same provider to standalone Whiteboard Script and nested time/log bodies. Export existing keyword and unit tables rather than duplicating them. Add snippets only after their parse tests pass.

Verify the real surfaces

Add a live note-editor story with open completion menus. Check light and dark mode, desktop and mobile, keyboard and pointer acceptance, long details, scrolling, an editor inside a dialog, and query/time/log bodies.

Decision

Build one completion architecture, not more local sources.

The shortest safe path is a shared tooltip theme, one fence resolver, per-editor provider configuration, and nested dispatch to the existing WQL provider. Whiteboard Script then joins that same path with a new grammar-aware source. Styling alone is a small patch; doing it first still has value because every later provider will inherit the corrected menu.

Evidence came from static inspection of the named source and test files, followed by an independent read-only review. No production behavior was changed. Browser verification for this deliverable applies to this report and its annotation controls.
