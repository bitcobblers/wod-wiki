Findings

  1. Two "Workout Complete" UIs, zero shared code. The dialog renders ReviewGrid from in-memory Segments; the TV renders its own aggregateProjections over Cast RPC. Any results UX change must be made twice.
  2. Divergent post-run destinations. Journal/canvas runs stay in the dialog; WallClockPage navigates to /results/:id. Same event, two endings.
  3. Three read currencies (raw Session.logs, WQL RowsQueryResult, derived Entry scalars) mean the same workout surfaces as different fields/units per screen: load lb vs tonnage vs volume vs work.
  4. PR badges are cosmetic. Rendered in storybook mockups and a regex in fieldProjection.ts:181-190; no PR computation exists in the codebase.
  5. RPE capture lives only in the in-note table (surface 5). The completion flow captures missing actuals (CollectionWizard) but never session RPE.
  6. The four legacy stacks are deleted (2026-10-22): ResultsView + Workbench, HistoryPostList → unrouted pages, JournalDateScroll, DOM twin. One dead import surface remains — the review-grid-index barrel now has no importer.
  7. Unification is already specced — the storybook NoteSessionLedger proposal is the standard the decisions above point at; no app code started.

Decisions for the rework

Recorded 2026-10-22 from the annotated review of this document.

  • Post-run destination — decided. The dialog is supported for the home page and the syntax/guide pages. For regular journal workouts the output renders under the block that was just run, with a link to /results/:id for full control — that is where dashboards and graphs land, later.
  • Results rendering — decided: standardize. One shared read currency and a standard way to render session records, with row-level flexibility kept: #tags allow custom metrics to be added to tagged rows.
  • PR badges — decided: support both. A computed PR and a tagged PR. #tags carry that function — a hashtag marks a row as a PR the same way a hashtag carries any other function.
  • Move RPE capture into the completion flow? (still open)
  • Delete the four unwired stacks — done (2026-10-22): ResultsView + Workbench, HistoryPostList → ListOfNotes → CollectionsPage/NotebooksPage, JournalDateScroll, buildResultListItemDOM.
