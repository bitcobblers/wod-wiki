Code review correctionsWhat reading the source changed about the report's assumptions.

N1 is a save race, not fence stripping

The serializer is byte-preserving (round-trip tests in packages/core/tests/SectionParser.test.ts pass unclosed fences through unchanged). The report's repro types the closing fence as the final action on the last line. That produces no cursor-line change and no blur, so the only persist path is the fire-and-forget page-hide flush in apps/playground/app/hooks/useEditorSave.ts, which races the IndexedDB write. The stored document then ends before the fence, and an unclosed dialect fence yields no runnable block, so Run disappears. Both reported symptoms come from one lost write.

N2's buttons were never panel switches

ClockControlModeToggle in apps/playground/src/clock/ClockCommandBoard.tsx switches keyboard Enter behavior and persists a preference. It renders no panel, so the observed aria-pressed change with nothing appearing is the component working as built. Rep entry exists but opens as a centered fixed modal reached from a different control. The fix makes these real inline toggles on touch hosts.

N4 is cqw bands exceeding viewport height

At 844px wide the runner selects the General surface, whose container-query-sized bands sum past 390px of height. The hero clips top and bottom, taking the exercise label and up-next caption with it. The panel-size context already exposes an isShort flag for exactly this case; the General surface just never consumes it.

N6 has a one-class cause

Every band in the mobile hero is fixed-height except the up-next caption, whose comment claims reserved space but whose markup has no height utility. It collapses at Ready and grows once the runtime starts; the centered hero shifts by about half the delta, the observed 8px. Reserving the caption height should drive the delta to zero.

#11's warning is correct behavior

The welcome sample references "Count Down", and no matching effort exists in the catalog. The reference-resolution system surfaces unknown efforts on purpose. The sample should change to a movement that resolves; adding a fake alias to silence a demo would pollute the catalog.

`time` fences are valid

The report's ```time block looked like a possible typo for the wod fence. It is not: the section parser accepts time and log dialects and maps time to a runnable block. No syntax change is needed for N1.

HighWave 1

N1: Reload loses the closing workout fence and Run disappears

Functional. Evidence: 50-latest-note-before-reload.png, 51-latest-note-after-reload.png. Reproduced on 2158 and 2160, twice on 2158.

Cause
Typing the closing fence on the last line triggers no line-change or blur flush. The page-hide flush is fire-and-forget and races the IndexedDB write, so the tail of the document is lost. An unclosed dialect fence parses as plain code with no runnable block.
Change
Make Save the explicit persistence contract. Add a visible Save affordance (desktop and mobile), Cmd/Ctrl+S handling, and dirty / saving / saved / error indication. Await the save; warn on reload, close, and SPA navigation while dirty. Keep the raw draft untouched; do not rewrite the serializer or section splicing.
Files
  • apps/playground/app/hooks/useEditorSave.ts
  • apps/playground/app/pages/NoteByIdPage.tsx
  • apps/playground/src/components/organisms/editor/NoteEditor.tsx
Acceptance
  • Type body plus a complete fenced block, press Save, reload: stored source and editor content are byte-equal, including fences, blank lines, multiple blocks, and property edits.
  • With unsaved edits, reload and SPA navigation warn; confirming the warning discards intentionally.
  • After Save, a ```time block still shows Run.
  • Covered at desktop and mobile viewports, hard reload and SPA navigation.
Tests
Extend apps/playground/app/hooks/useEditorSave.test.ts and e2e/live-app/note-persistence-save-load.e2e.ts; extend e2e/pages/BaseNotePage.ts helpers.
MediumWave 1

N3: Property draft cannot be dismissed

UX. Evidence: 52-latest-add-property.png, 56-property-after-escape.png.

Cause
"Add property" immediately patches an empty property: row into the document, which the commit path persists, so the draft survives reload. The row's key/value editors have Enter and blur commit only; there is no Escape handler, Done, or Close.
Change
Turn Add property into a true local draft: Done validates and applies the values to the editor, Close and Escape cancel and discard. No empty row is ever written. Opening or closing metadata preserves body scroll. Explicit Save persists applied values, per the N1 contract.

  • Enter a key and value, press Done: the row appears in the editor; before Save, reload discards it; after Save, it persists.
  • Body scroll position is unchanged when the panel opens and closes.

Risks, limits, and source-report scopeWhat could slip, and what this retest never claimed.
