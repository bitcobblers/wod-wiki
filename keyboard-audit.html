7 · Conflict & inconsistency findings

  1. RESOLVEDCtrl+←/→ now means one thing. Editor metric-token jump keeps the chord (cursorFocusExtension.ts:286-289); the workbench view switch moved to Ctrl/Cmd+Shift+←/→ (ResponsiveViewport.tsx).
  2. RESOLVEDOne search chord: Ctrl/Cmd+/. The k and p chords were removed from AppContent's listener (AppContent.tsx) and the editor's Mod-P palette binding was deleted; tooltips, comments, and docs now say Ctrl+/. The capture-phase listener still has no typing guard — deliberate, so search is reachable mid-edit.
  3. PARTIALTwo ways to invoke search remain. Bare / focuses the filter strip on queriable-list views; Ctrl+/ opens the palette everywhere. The k/p palette chords are gone.
  4. SPLITEnter is overloaded with an outlier — what this means concretely. Most screens agree Enter = "confirm the thing I'm looking at": picking a palette result, activating a focused library row, submitting a WQL query. Your muscle memory for Enter is "do the highlighted thing". The timer breaks that contract: pressing Enter there doesn't confirm anything visible — it silently advances to the next workout block/lap (wallclock-panel.tsx:419-445, a window-level listener). Two failure modes: (1) you're on the timer screen, hit Enter out of "confirm" habit — a lap you didn't mean to start gets skipped; (2) every other "go to next item" action in the app uses Tab, ↓, or →, so the timer's next-on-Enter teaches a second, conflicting meaning for the same key. The universal play/pause gesture (Space) is also unbound on the web timer, so there's no safe "do something with the timer" key at all.
  5. GAPNo start/pause/stop keys on the web timer. Only Enter→next and hardware Volume-Up. No Space (universal play/pause); Escape→stop exists only on the Cast receiver (receiver-rpc.tsx:519-532).
  6. RESOLVEDWrap-in-time-fence rebind: Ctrl/Cmd+Alt+W. The old Ctrl/Cmd+Shift+W collided with browser "close window" (whiteboard-autocomplete.ts); the chord is now Mod-Alt-w, which no browser claims.
  7. RESOLVEDCtrl/Cmd+S saves now, and autosave is coalesced. The editor keymap handles Mod-S (blocking the browser's Save-Page dialog) and flushes the pending draft through the note save pipeline; useEditorSave lost its 800ms idle timer — drafts persist on line change, blur, pagehide, and explicit save instead of minting a revision at every typing pause. Fewer block revisions, same pinning safety (session start still flushes first).
  8. SPLITSpace-to-activate is partial. DOM rows accept Enter+Space (LibraryRow.tsx:127, PropertyTable.tsx:173), palette results accept Enter only (useListState.ts:118-123).
  9. GOODEscape is the one consistent verb — 15+ sites all mean dismiss/cancel/back-out. Solid convention to build on.
  10. GOODCompletion keys are consistent across query surfaces and frontmatter: Ctrl+Space invoke, ↑↓ navigate, Tab/Enter accept, Escape dismiss.
  11. SIGNALPrototypes imply a ←/→ = previous/next convention (ProtoTimerMobile.tsx:62-63, QueryBlockComposerPrototypePage.tsx:240-241) that no production screen implements.
  12. DEBTReceiver debug key logger (receiver-rpc.tsx:464-467) is marked removable — cleanup candidate.
