# Ontology Changesets (`ontology/changesets/`)

Gated bidirectional changeset graphs (`<timestamp>-<slug>.trig` + `<timestamp>-<slug>.md` review summaries) generated by `bun run ontology:changeset`.

## Lifecycle

1. **Propose** (Code -> Ontology):
   ```bash
   bun run ontology:changeset propose [--base <ref>] [--staged] [--slug <slug>]
   ```
   Creates a `pending_approval` `.trig` changeset graph with `prov:` metadata and proposed `:domain`, `:code`, and `:bridge` triples, plus a `.md` human review summary.

2. **Review & Approve**:
   ```bash
   bun run ontology:changeset list
   bun run ontology:changeset approve <id>
   # or reject:
   bun run ontology:changeset reject <id> --reason "..."
   ```

3. **Apply & Align** (Ontology -> Code):
   ```bash
   bun run ontology:changeset apply <id>
   ```
   Refuses to apply unless `changeset:status` is `"approved"` (or `--approve` is explicitly passed). Merges approved triples into `ontology/bridge/changesets-applied.ttl`, marks the changeset `"applied"`, and triggers `sync-from-ontology`.

## Shakedown Notes & Edge Cases

- **Modified symbols in diffs**: When an exported TypeScript symbol (e.g. `export type TestId`) is modified in place, `git diff -U0` shows both `-export ...` and `+export ...`. `extractDiffSignals` deduplicates symbols present in both sets so they are not emitted as spurious `:removed:code` deletions.
- **SHACL compliance on merged triples**: `ontology/validate.sh` loads all `.ttl` files under `ontology/` (including `ontology/bridge/changesets-applied.ttl`) into the validation data graph. Generated `:code` triples must therefore satisfy `ontology/shapes/code-shapes.ttl`:
  - `code:Symbol` requires `code:scipId` (`"<filePath>#<symbolName>"`) and `code:definedIn` (`code:File`).
  - `code:TestId` requires `code:testIdKey` (`"TEST_IDS.<KEY>"`) and `code:testIdValue`.
  - `code:Route` requires `code:routePath` (`"/..."`); `code:WebMcpTool` requires `code:toolName`.
  - `bridge:testId`, `bridge:route`, and `bridge:specFile` are `owl:ObjectProperty` edges (expecting `code:TestId` / `code:Route` / `code:File` IRIs, never raw string literals).
- **Keeping `ontology/generated/` fresh**: `apply` runs `sync-from-ontology` (`ontology:validate`, `ontology:codegen`, `ontology:build`, `check:test-ids`, `check:agent-parity`). If `ontology:build` runs before `ontology:query -- --chains` is needed in CI, run `bun run ontology:query -- --chains` afterward to keep `ontology/generated/chains.md` in sync.
