# Inside the WOD Wiki Runtime

The **Workbench** section opens up WOD Wiki's internals so engineers, coaches, and contributors can trace how plain-text Markdown turns into a live workout clock and queryable analytics.

---

## The 4-Stage Execution Pipeline

Every workout `Note` flows through four deterministic, inspectable stages:

1. **Parse (`packages/lang`)**: `whiteboardscript.grammar` (Lezer) → `syntax-parser.ts` → `semantic-classifier.ts` → dialect stack → `ICodeStatement[]` carrying typed `IMetric` values (`time`, `rep`, `effort`, `rounds`, `distance`, `resistance`, `action`, `rest`, `equipment`).
2. **Compile & Shake-Out (`packages/engine`)**: The JIT compiler resolves `Property Note` definitions, `Scoped Property Override`s, and the `Metric Shake-Out Queue` (`parser → dialect → compiler → runtime → user → analyzed` origin precedence) without overwriting earlier layers.
3. **Execute (`RuntimeStack` & `SessionClockProjection`)**: Blocks initialize in constructors, push onto `RuntimeStack` lazily, emit immutable `OutputStatement` / `EventRecord` entries as time and reps advance, and clean up via consumer-managed `dispose()`.
4. **Persist & Query (`packages/storage` & `packages/wql`)**: Finished runs persist as `Session` records in IndexedDB (or SQL/API), immediately queryable via WQL pipelines and `Dashboard Widget`s.
